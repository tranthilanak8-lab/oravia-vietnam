ORAVIA V15 — PRODUCTION SETUP

Recommended architecture
1. Cloudflare Pages — website hosting/CDN
2. GitHub — source-code version control and change history
3. Cloudflare Worker / Pages Function — secure enquiry endpoint
4. Database/CRM — lead records
5. Transactional email provider — internal alerts + customer confirmations
6. Separate secure document-upload flow for visa documents
7. Payment provider — added only after quote/confirmation

Why Git integration
Use GitHub integration rather than dashboard drag-and-drop for the long-term ORAVIA project. It gives the project a source of truth, version history and a cleaner path for future updates. Cloudflare Pages supports GitHub/GitLab integration and automatic deployments when changes are pushed.

Production environments
- Preview: used for testing changes
- Staging: optional protected review environment
- Production: the public ORAVIA website

Domain plan
- Primary: ORAVIA domain chosen by owner
- www: redirect or canonical host
- app/admin: only if a separate internal dashboard is later required
- mail: business email handled separately from the website host

Email plan
Recommended addresses:
- hello@DOMAIN
- visa@DOMAIN
- travel@DOMAIN
- bookings@DOMAIN
- privacy@DOMAIN

Lead flow
Visitor
 -> Visa/Tour/Cruise form
 -> secure server-side endpoint
 -> validation + spam protection
 -> lead database/CRM
 -> internal email alert
 -> customer acknowledgement
 -> staff follow-up
 -> quote
 -> confirmation
 -> payment
 -> booking/service
 -> review request

Visa document flow
Public enquiry form
 -> case assessment
 -> secure, limited-time document upload link
 -> authorised staff only
 -> document retention/deletion policy
Do not put passport scans or payment-card data into the ordinary enquiry form.

- Final logo/assets

- Real email addresses
- Real CRM destination
- Real form endpoint
- Spam protection
- Analytics

- Backup/recovery process
- Mobile QA
- Form QA
- Email delivery QA

Change-management rule
Every website change should be made against the source-code version, tested in preview/staging, then deployed to production. Keep the previous production version available for rollback.

Important
Do not put secrets in HTML, CSS or client-side JavaScript:
- API keys
- database credentials
- SMTP passwords
- payment secrets
- private tokens
